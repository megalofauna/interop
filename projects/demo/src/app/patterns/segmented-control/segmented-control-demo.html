Segmented control Pattern

Also known as segmented button, button toggle group, toggle group, content switcher, segment group.

A pattern: a template of the radio group. Segmented tabs share its look, and the theme switcher is built from it.

A segmented control is a radio group drawn as a row of segments: interop-radio-group="segmented". It is still a radio group. Screen readers announce each segment as a radio button, checked or not, and its position in the set. Tab reaches the control once, and the arrow keys move the choice. Use it to pick a value or a view of the same content. To switch between different sections, use tabs.

Vertical

itx-orientation="vertical" stacks the segments, each as wide as the widest. Use it where the row does not fit: a narrow column, or labels that run long once translated.

Fitting the space

A row that runs past its container fails reflow (WCAG 1.4.10). Three ways stack it, and with none the control stays a row:

  • itx-orientation="vertical" stacks it always.
  • --itx-segmented-orientation: vertical, set in the page's own @media or @container rule, stacks it below a width you choose. No script.
  • bindSegmentedFit(), or interop-segmented-fit in Angular, measures the row and stacks it only when it does not fit, whatever the labels say once translated. The month control in Home and End uses it: narrow the window to see it stack.

Two looks

The selected segment is a raised pill on a filled channel. Its fill is only 1.2:1 against the channel in light and 1.45:1 in dark, so its edge carries the selection: 3.76:1 and 5.83:1 (WCAG 1.4.11). An inverted pill, the same fill as an on switch, is a set of token values: 17.9:1 against the page in light, 16.7:1 in dark.
