Theme switcher Pattern

Also known as theme toggle, dark mode toggle, appearance.

A pattern, built from a segmented control, with bindColorScheme().

Three options: Light, Dark and System. System is the default: the page follows the operating system until the user chooses. A two-state toggle has no way back to System, so one press stops the page following the system for good. The group's name is "Theme" whatever is chosen, and changing it needs no announcement: a screen reader says the radio button it lands on.

How the page changes

Every Interop color is a light-dark() pair, and interop.css declares both schemes on the root, so System costs no script. bindColorScheme() sets itx-color-scheme="light" or "dark" on the root and remembers it in local storage; System removes both. It follows a change made by another switcher or in another tab.

Colors of your own follow the switcher only through light-dark(). A prefers-color-scheme media query reads the system and ignores the switcher.

No flash on load

The helper runs after the page renders, so a page reloaded in the scheme the user chose would first paint in the system's. Put this in the <head>, before the stylesheets. The meta tag lets the browser paint its own canvas in the right scheme before any CSS loads.

Two states

If a design insists on two states, use a button with aria-pressed and a name that does not change. Not a switch role, which screen readers report unevenly, and not a sun or moon icon alone, which can mean the current theme or the next one.
