Dialog

Also known as modal, modal dialog, alert dialog, sheet, lightbox.

A dialog is a native <dialog interop-dialog>. A button with command="show-modal" opens it. The browser keeps focus inside it, makes the page behind it inert, closes it on Escape, and returns focus to the button that opened it. Interop adds the look, the motion, and stops the page scrolling behind it. It needs no script.

Name every dialog with aria-labelledby pointing at its heading, so a screen reader says what it is for when it opens.

Confirm an action

The buttons sit in <form method="dialog">: pressing one closes the dialog, and its value becomes the dialog's returnValue. Escape leaves it empty. Focus starts on the least destructive button.

A close button

The close button uses command="request-close", which takes the same path as Escape: the dialog fires cancel first. Type in the field, then press Escape or the close button: the cancel listener keeps the dialog open and says why. A browser lets a page refuse Escape only once per user action, so Escape pressed again and again closes it anyway; a click on the close button is refused every time. Put autofocus on the first field, or the close button takes focus on opening.

Close on a click outside

closedby="any" also closes the dialog on a click outside it. Use it where nothing is lost: never for a form or an alert. Safari does not support it yet, and there the dialog closes with Escape and its buttons.

Alert dialog

For an urgent message that needs an answer, add role="alertdialog" and point aria-describedby at the message, so it is read with the title. closedby="none" turns off Escape and clicks outside, so only a button closes it.

Long content

The dialog is never taller than the window. Its content scrolls inside it, and scrolling past the end does not move the page. tabindex="-1" autofocus on the heading puts focus at the top, so a screen reader starts at the beginning and the arrow keys scroll. Chrome ignores autofocus on the dialog itself.
