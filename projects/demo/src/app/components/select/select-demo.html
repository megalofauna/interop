Select

Also known as dropdown, dropdown list, combo box, pop-up button, picker, select menu.

A select is a native <select interop-select> with a field's look. The browser opens it, moves through it with the keyboard, finds an option as you type, and submits its value with the form. On phones it opens the system's picker. It needs no script.

In Chrome and Safari 27 the list of options takes the house look: it reads the popover's tokens, the chosen option shows a check, and long options wrap. Firefox and older browsers draw the list themselves.

One choice

Groups and separators

An <optgroup label> names a group in every browser, and screen readers announce the name. An <hr> draws a line between options. A disabled option is shown, and cannot be chosen.

Options with more than a name

Where base-select is supported, an option can hold any markup, and a <button> with <selectedcontent> shows a copy of the chosen option in the closed select. Every option needs text: other browsers keep only the text, and screen readers read it. Avoid ids inside an option, since the copy repeats them.

Sizes

Options in the page

With size above 1 the options show in the page as a scrolling list, as many rows as size. For one choice from a short list, a radio group shows every option without scrolling.

Several choices

multiple is styled, and the dev audit warns about it. In testing with screen reader and keyboard users, a native multiple select reached 25% task success, against 100% for a single select (Higley, 2019). Use a checkbox group instead.

Bound to a signal

Bind [value] and listen to (change), or use Angular forms: they work with a native select.
