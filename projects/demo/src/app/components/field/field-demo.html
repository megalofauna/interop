Field

Also known as text field, text input, text box, textarea, form field.

A field is a label, an optional hint, an optional error, and a native control, in that order: <input interop-input>, <textarea interop-input> or a select interop-select. The control's own attributes do the work: type, name, autocomplete, inputmode, required.

The hint and the error sit above the control, where autocomplete lists and on-screen keyboards cannot cover them. The hint is wired with aria-describedby; bindValidation() fills the error, shows it, and adds it to aria-describedby while it shows.

Validation

interop-form calls bindValidation(). The browser checks the constraints; Interop decides when to show the result, and says it in the page. Try it:

  • Leave a field empty and move on: nothing yet. An empty required field waits for submit.
  • Type "abc" in the email field and move on: the format error shows at once.
  • Fix it: the error clears as you type.
  • Submit with errors: the summary lists them and takes focus. Each link moves to its field.

    Units

    Password

    A button beside the field shows the password, so people can check what they typed. It is an invoker: command="--toggle-password" aimed at the input. It keeps its label and reports its state with aria-pressed. It is hidden until script runs, and the password is hidden again when the form is submitted, so the browser does not save it as plain text.

    Character count

    The count shows how many characters are left as you type, and a screen reader hears it once typing pauses. Going over the limit is allowed: the count says by how much, and the field is invalid until it is shortened.

    Read-only and disabled

    A read-only field can still be focused, read and copied, and its value submits. A disabled one can do none of these, so prefer read-only for a value the user should see.
