Toolbar

Also known as command bar, action group.

A toolbar holds three or more controls that act on one thing, such as the formatting buttons of a comment box. It is one Tab stop, and the arrow keys move between its controls, so a keyboard user reaches the text area after it in one press. You write the markup: role="toolbar", focusgroup="toolbar" and a name. Browsers with focusgroup move focus themselves. Elsewhere the InteropToolbar directive from interop/toolbar, or bindToolbar(root) from interop, does it.

One or two buttons, or a form's Save and Cancel, are not a toolbar. Leave them as buttons, where Tab reaches each one.

A comment box

@for (group of groups; track group.label) {
@for (action of group.actions; track action.label) { {{ action.label }} }
}

Select some text and press a button. Focus returns to the comment with the new text selected, and Ctrl+Z or Cmd+Z undoes the change.

Keyboard

Key Does
Tab, Shift+Tab Enters and leaves the toolbar. Coming back lands on the last button used.
Left, Right Move between buttons, across the groups. Right to left flips them. Add wrap to focusgroup to wrap at the ends.
Home, End Go to the first and last button.
Enter, Space Press the button.

What goes inside

Buttons, and named role="group" elements around related buttons. A screen reader announces the group's name as focus enters it, and the toolbar spaces groups apart. A disabled button is skipped by the arrow keys; one with aria-disabled="true" is not, so it can still say what it does.

A text field and radio buttons use the arrow keys themselves, so focus cannot leave them with the arrows. Put at most one text field in a toolbar, last. For one choice of several, use buttons with aria-pressed, or a segmented control beside the toolbar.

For a vertical toolbar, write focusgroup="toolbar block" and aria-orientation="vertical". The browser does not announce the orientation from the token.
