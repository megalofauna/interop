A collapsible hierarchy in one of two tiers. Bare [interop-tree] is a nested-list disclosure structure with real links and a natural tab order. interop-tree="select" is a role="tree" widget with one tab stop, roving focus and typeahead. Neither uses a virtualizer, so collapsed branches stay findable by find-in-page.

role="tree" is not a label, it is a behaviour contract: one tab stop for the entire widget, roving focus, typeahead, arrow keys that expand and collapse, and a selection model. Signing that contract and then not honouring it is worse than not signing it — which is why Interop will not apply it for you.

Use the navigate tier (the default) when

  • rows are links that take the user somewhere;
  • rows contain form controls, buttons, or other interactives;
  • the hierarchy is a way to get to content, not the thing being operated on — nav sidebars, docs contents, browse lists.

Use the select tier when

  • the user operates on the hierarchy — picks nodes, checks them, reorders them;
  • a single tab stop is what you want, because the tree is one control among many;
  • rows carry no other interactive content.

The tier decides several downstream questions for you. Checkboxes are real <input> elements in the navigate tier (free form participation, free tri-state via indeterminate) and aria-checked in the select tier, where interactive descendants are unreachable. The twisty is a real <button> in the navigate tier and an aria-hidden affordance in the select tier. Put the wrong thing in either and devMode says so.
