A field is the whole unit — visible label, control, helper text, validation errors, and the ARIA wiring between them. Two components ship: <interop-field-input> and <interop-field-textarea>. Both implement ControlValueAccessor, so they drop into reactive forms unchanged.

A filled slab with a single rule along its bottom edge — the shape is borrowed from IBM Carbon's text input. The label sits above at 12px, the value inside at 14px, helper text below at 12px.

Identical to the input in every respect but three: 11px of block padding instead of a fixed height, a 40px minimum so an empty textarea lines up with an input beside it, and slightly looser leading for multi-line text.

The most distinctive state. An invalid field takes a 2px inset ring, a recoloured underline, an inline error glyph, and the message below in the same red. Focus outranks the error ring — a focus indicator that can be one of two colours is a worse focus indicator.

itx-size steps the control height — sm 32px, md 40px (the default), lg 48px. Inline padding and type size hold at every step; density is a separate axis. On a textarea the attribute sets the minimum height, since content decides the rest.

One --itx-field-* namespace covers both components. Set any of these on an ancestor — [interop-root], a form wrapper, or the field host itself.
