--itx-surface is the background a component stands on, and the engine writes it from depth — layer N is surface-N. --itx-surface-above names the one the next layer would paint. The counter stops at layer 2, so surface-3 is only reached that way.

There is no -below, because a raise and a recess at the same depth are the same colour: light from above separates them, not the substrate. A recess declares itx-sink and reads --itx-surface. Add itx-layer to nest one step further from the page; nesting compounds. itx-layer="2" pins a depth wherever the element sits.

Opacity is per-scheme because contrast is not symmetric: the same 25% reads about 2.15 on dark and 1.66 on light. It has to be baked into the colour rather than carried as a number — light-dark() takes a colour only, so light-dark(33%, 25%) silently resolves the whole color-mix to transparent, which measures 1.00 and looks like a border that is not there.

At fixed lightness and chroma, contrast barely moves around the hue circle. Chroma is the variable that breaks it: spread across these five hues at L 0.60 is 0.06 at chroma 0.02, 0.42 at 0.105 and 1.51 at 0.22. Capped at 0.16, every hue clears its floor without a per-hue correction.

Four tokens the measurements retired rather than renamed. A per-family label on a fill collapses to one --itx-role-text-inverse, because one label clears all five. A label on a wash disappears entirely, because the family text already clears its own wash.

Every library selector is zero-specificity and sits inside the interop cascade layer, so any rule you write wins on contact.

Change one component

Set the component's own token. No layer block touches it.

--itx-dialog-background: var(--itx-role-background-interactive);

Change a role everywhere

Roles are declared once and inherit. Set one on any ancestor and everything below follows. 

--itx-role-edge: oklch(0.55 0.01 250);

Move every surface

Redeclare the surfaces, or the tint pack that supplies their chroma and hue. Retuning the ramp and retinting a subtree are the same act, and both are ordinary CSS. 

--itx-tint-dark: 0.012 30;
--itx-surface-0: light-dark(oklch(0.97 var(--itx-tint-light)), oklch(0.2 var(--itx-tint-dark)));

What gets overwritten

--itx-surface is written by the engine at every layer boundary, so a value set on an ancestor is replaced one layer down. So are the two fills derived from it. Reach for a component's own token instead.

Three constraints to design around.

The state ramp has two rungs

A control's plane sits a full step out from its surface and a state one half-step above that. There is no third: at a tenth of a step out, three of the four text tiers stop clearing. A component that needs more states than that carries them with a mark or an edge, not with another fill.

Chroma costs contrast

Two colours at the same lightness measure differently if one carries more chroma, which is why --itx-accent-chroma is capped rather than free. Raising it is allowed and it is checked: npm run lint measures every pairing in a browser and fails on a miss.

Colours are authored, not computed

The surfaces and the text tiers are literal values in styles/themes/protocol/ladder.css. Adding a family means one hue number and four derived roles. Nothing solves a palette at runtime.
