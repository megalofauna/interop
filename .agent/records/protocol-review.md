# Protocol plan: critical reviews and responses

## First review

2026-10-31. A reviewer with no prior context read the first draft of the plan,
the binders and the directives, and measured in headless Chromium. Its verdict: not approvable as
drafted. Every finding was accepted. The revised plan carried the
answers; this record keeps the evidence and the reasoning.

### Measurements

| What | Result |
|---|---|
| All binders + `toast` + `announce` + `drawIcons`, one bundle | 11,587 B gzip |
| Each binder bundled alone, summed | 18,794 B (double-counts shared code) |
| `guardActivation` alone | 11,779 B: it imports `audit.ts` |
| Everything in `public-api` | 23,632 B |
| Insert 2000 rows (22k nodes, 2000 icons, 2000 badges) | 6.1 ms with no observer; +2.9 ms with one joined selector; +4.0 ms with 22 separate selectors |
| 1000 badges × 3 attributes × 60 frames | unfiltered: 180k records, +55 ms; filtered: 60k records, +15.5 ms |
| Rebind per element | `bindTabs` 9.3 µs, `bindScrollArea` 5.1 µs, `drawIcons` 1.6 µs |
| Full-document scan, one joined selector, 20k nodes | 2.6 ms |
| `auditInterop()`, 20k nodes | 8.9 ms per run |

Matching and observing are cheap. The contract was the problem.

### Findings and answers

| # | Severity | Finding | Answer |
|---|---|---|---|
| 1 | Blocker | A MutationObserver cannot see `.value` writes. `slider.ts` repaints on every Angular render because a bound or form-written value fires no event; character count listens only to `input` and `reset` | The slider and character count behaviors wrap the `value` property of their own input, in core. Specs for `FormControl.setValue`, checked in WebKit and Firefox. Fallback: an `interop-update` event that packs fire after writing |
| 2 | Blocker | Rebinding on every attribute change loses closure state: the badge's `previous` count (announce never fires), the character count's announce timer, the tooltip's open state, the tabs' observer | Contract gains `update(changed)`. Each behavior declares configuration attributes (a change rebinds) and state attributes (a change calls `update`) |
| 3 | Blocker | `ngSkipHydration` is allowed only on component hosts (NG0504); template-less pack directives cannot carry it. Badge, icon and code block render on the server today and would render empty | Packs may render markup that core defines, from core's pure functions. Pack components hydrate normally. Core behaviors skip a host that is already rendered |
| 4 | Major | `attributeFilter` takes exact names, so "watch `itx-*`" means no filter: every `class`, `style`, `aria-*` write. Binders write `itx-*` themselves (`itx-code-line`, `itx-color`, `itx-color-scheme`) | The filter is an exact list generated from the registry. The loader ignores attributes behaviors declare as their own output |
| 5 | Major | "Bound before first paint" holds only for script-inserted markup. Parsed and server-rendered HTML can paint first. jsdom has no paint, so a unit spec cannot prove it | Claim narrowed to script-inserted markup. Parsed markup relies on the rule that markup works before script. A `scripts/cdp/` check measures which behaviors can flash |
| 6 | Major | `(element, options?) => cleanup` fits few binders: `bindFilter(input, list, …)`, `bindTooltip(trigger, tooltip)`, `bindShortcut(button, keys)`, `bindSelectAll(parent, group)`, `bindCharacterCount` with a required limit, `drawIcons(root): void`. Page nav binds `:scope > ul`, so a late `<ul>` never binds | Binders keep their signatures. Each registry entry is a written wrapper that reads attributes and calls the binder. A behavior that needs descendants binds the host and finds them when it needs them |
| 7 | Major | IDs resolved once at bind time go stale when the target renders later (`@if`, `@defer`). `@for` rows would need generated IDs | Resolve at event time where possible. Otherwise a waiting list from ID to elements, with `id` in the filter. Angular passes element references through `configure()` |
| 8 | Major | The audit ships to production through `guardActivation` (11.8 kB). Coupling the loader to the audit would make every app pay it | Existing bug, fixed first. Rule: the audit may import the loader, never the reverse. Size test enforces it |
| 9 | Major | Numbers wrong: 19 Angular entry points, 10 CSS-only, 18 classes call a binder, 9 function options, 11.6 kB. Nine specs and `test-setup.ts` import Angular | Recounted. The guardrail's allowlist is generated by a script and excludes specs |
| 10 | Major | `bindRadioHomeEnd`, `bindSelectAll` in no batch; `guardActivation`, `scopeSelectAll` are document-wide and nobody starts them | `startInterop()` installs both document guards, each can be turned off. The two binders join batch B |
| 11 | Major | Phase 3 deletes directives before the demo starts the loader (phase 6). Batch C needs `configure()` from Angular before the pack exists | The demo starts the loader in phase 2. Batch C runs after the Angular pack |
| 12 | Major | Six binders hold elements through document or window listeners. An element removed while the loader is stopped never cleans up and keeps responding. `removedNodes` lists only subtree roots | `stopInterop()` unbinds everything. The loader walks removed subtrees for bound elements. A spec covers removal while stopped |
| 13 | Major | `configure()` timing undefined: React effects run after paint, so the first bind uses defaults; fresh objects every render would rebind every render | Options set before the first bind bind once; set after, they go through `update`; compared shallowly. Packs keep options objects stable |
| 14 | Major | An empty code-block host with the source in an attribute shows nothing until the lazy highlighter loads, shifts layout, shows nothing without JS, and carries the source twice in server HTML | The source stays as `<pre><code>` children. The behavior adds colors |
| 15 | Minor | Eager registry has no budget: an icon-only app goes from 0.6 kB to 11.6 kB | `startInterop({ behaviors })` takes a smaller registry. Size test: loader under 1.5 kB, full registry under 12 kB, gzipped |
| 16 | Minor | The audit observer watches every attribute and text change and reruns the full audit per batch: 8.9 ms on 20k nodes, so each loader write costs about 9 ms in development | The audit ignores the loader's writes and batches runs per frame |
| 17 | Minor | The badge loses Angular's `LOCALE_ID` | Locale from the nearest `lang`, then `navigator.language`. The Angular pack can pass `LOCALE_ID` through `configure()` |

Zone.js: `provideInterop()` starts the observer outside Angular's zone so binding work does not run
change detection. A plain `startInterop()` in a zone.js app's `main.ts` should do the same.

### The rule that changed

The first draft said a pack has no templates. Finding 3 showed that breaks server rendering and
hydration. The rule now: **a pack renders only markup that core defines, from core's pure
functions.** Rendering markup core defines is convenience, not behavior. Approved by the user
2026-10-31.

## Second review

2026-10-31. A second reviewer with no prior context read the second draft and this record, tested in
Chromium and WebKit with Playwright, and prototyped the loader. Verdict: not approvable. Three
answers to the first review failed in code, and the draft contradicted itself on phase order. Every
finding was accepted. The third draft carried the answers. The common cause: core was asked to do
framework jobs, catching every value write and rendering into hosts a framework also renders.

### Measurements

| What | Result |
|---|---|
| Instance `value` wrapper, setter calls | `.value =` only. `valueAsNumber`, `stepUp()`, `form.reset()`, `defaultValue`, the value attribute, a `max` clamp and `setRangeText()` all bypass it |
| Angular 21 signal forms, range and number fields | written with `valueAsNumber` (`@angular/forms` `signals.mjs:751`) |
| Wrapper with React | Interop first: React skips its value tracking. React first: React's setter is replaced |
| All binders + `toast` + `announce` + `drawIcons` | 12,082 B gzip |
| Loader prototype, with waiting list, sweep, filter, update and `configure()` | 1,400 B; 1,763 B with both document guards |
| Clearing 2000 rows (22k nodes) | 5.5 ms querying each removed subtree; 0.3 ms sweeping a Set by `isConnected` |
| Record order, insert then set attribute | `childList` before `attributes`, in one callback |
| Guard and an `aria-busy` section | a link inside is not followed and a button's handler does not run |
| `attributeFilter: ['interopTooltip']` | no records for the parsed attribute `interoptooltip` |

### Answers from the first review that did not hold

| First # | What failed | Answer |
|---|---|---|
| 1 | The `value` wrapper sees only `.value =`, misses Angular's `valueAsNumber` path, and breaks React's value tracking | Dropped. Behaviors listen to `input`, `change` and `reset`; code that writes a value calls `refresh(element)`; the Angular pack calls it on value changes (D9) |
| 3 | A pack component and a core behavior render the same host: `drawIcons` replaces Angular's nodes; the badge would announce twice or announce from the pack; "already rendered" never repaints stale server markup | One owner per host (D7). The pack's component owns its host, calls core for behavior, and marks the host so the loader skips it |
| 15 | Today's binders are already 12.1 kB, over the 12 kB budget; the guards push the loader past 1.5 kB | Budgets from measurements: loader 1.5 kB, guards 0.5 kB separately, registry 13 kB; rechecked when phase 0 starts |
| 12 | A WeakMap cannot be iterated, so `stopInterop()` cannot find its bindings | A Set of bound elements, swept by `isConnected` |
| 7 | An element inserted with its `id` set produces no attribute record | Each batch looks up the waiting IDs while the list is not empty |
| 10 | The guard cancels clicks inside any `aria-busy` ancestor, including the demo's progress example | Fixed in `3e37b085`: `aria-busy` stops a click only on the control that carries it |
| 4 | A record carries no author, so "ignore the behavior's own writes" cannot work | A behavior's outputs are never its inputs; the filter needs no author |
| 11 | Phase 2 required every binder registered while phase 3 registers them one by one; the demo would install the guard twice | The registry starts empty with a shrinking "not yet migrated" list; the demo's own guard call goes when the loader starts |

### New findings

| # | Severity | Finding | Answer |
|---|---|---|---|
| 1 | Blocker | No rule for a batch that inserts an element and then sets its attributes, so it binds and then rebinds | Removals, then additions, then attributes; attribute records ignored for elements bound in the same batch; configuration plus state is one rebind. Angular's write order is measured in phase 2 |
| 2 | Major | "One MutationObserver" is false: nine binders create their own, scroll area adds a ResizeObserver, every tooltip and shortcut adds a document listener, and a rebind recreates them all | Counts per behavior and a 500-tooltip benchmark in the browser runner. Tooltip and shortcut move to one shared listener each |
| 3 | Major | Icon drawing would exist four times; an SVG string cannot go through Angular's sanitizer | `iconParts(name)` returns data; every drawer uses it; no `innerHTML` |
| 4 | Major | The icon plan dropped `aria-label` and `aria-labelledby` tracking | Both are state attributes |
| 5 | Major | The code block's caption, copy button, tooltip and line numbers had no owner on a plain page | The markup is the template; an `interop-copy` behavior copies; the code-block behavior adds colors and line numbers |
| 6 | Major | No harness for what jsdom cannot test | A Playwright runner for Chromium and WebKit in phase 2; Firefox after a download is approved |
| 7 | Minor | `attributeFilter` is case-sensitive; five attributes are camelCase | Lowercase names; the five are renamed. The tooltip trigger gets no attribute at all: the behavior is on `[interop-tooltip]` and finds triggers through `aria-labelledby` and `aria-describedby` (D10) |
| 8 | Minor | 19 classes call a binder; the bundle is 12.1 kB | Corrected |
| 9 | Minor | Shadow roots, duplicate and never-appearing IDs unspecified | Document scope; duplicates resolve as `getElementById` does; waiting entries drop with their element; a dev warning for IDs that never appear |

### Rules that changed

Both approved by the user 2026-10-31:

- **Behavior lives only in core; a pack may call core.** A pack relaying a framework's value change
  to `refresh()`, or a pack component calling core's announce helper, is the protocol at work.
- **The tooltip trigger carries no Interop attribute.** The ARIA reference it needs for
  accessibility is the connection. `interestfor` is the native successor once every engine ships it.

### Bugs it found in the current code

The two fixed in `3e37b085`: the guard blocked clicks inside `aria-busy` regions, and
`guardActivation()` pulled the dev audit into production bundles (11,782 B to 348 B).

## Outcome

A third review found more problems of the same kind: owner markers, waiting lists, batch ordering
and hydration timing all came from a page-wide observer competing with the framework for the same
DOM. That observer and registry reimplemented the custom elements registry. The plan was dropped
and deleted. Components with behavior become light-DOM custom elements, where the import defines
the element and the browser handles discovery and lifecycle, or delegated document listeners. The
binders stay as their internals. The measurements above still apply.
